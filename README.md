# 抖音爆款视频分析 · douyin-viral-analyzer

> 一个用于**逆向工程抖音/TikTok 爆款短视频**的 [Claude](https://claude.com/claude-code) Skill。面向短视频创作者和 MCN，把一条已验证的爆款拆成可复刻的零件。

爆款不是玄学。每条火起来的视频背后都有可识别的结构:一个能在 1.5 秒内让人停下来的钩子、一段维持注意力的节奏、一个引发情绪共鸣或行动冲动的设计。这个 skill 的任务不是夸视频好,而是**像逆向工程一样把这些零件标出来**,让创作者下次能在自己的选题上重新组装。

## 它能做什么

从多个维度反推爆款原因,并产出可直接落地的复刻方案:

- **钩子拆解**(0–3 秒):第一帧画面、第一句台词、钩子类型与心理机制
- **脚本结构与节奏**:逐时间轴标注每段在做什么,抽象出可复用的脚本公式
- **情绪曲线**:标出情绪起伏,定位用户可能划走的断点
- **视听元素**:景别/运镜/转场密度、BGM、字幕花字、人物表演
- **公开数据比例分析**:互动率、评赞比、藏赞比、转赞比 —— 并**按视频类型校准**健康参考值
- **评论区洞察**:单评论级爆款、高频情绪、UGC 共创、创作者二次运营
- **爆款归因**:1–3 个核心爆点排序,并用评论区证据做**归因校验**
- **复刻清单**:脚本公式 + 5–8 条可直接开拍的选题变体 + 拍摄/剪辑要点 + 风险点
- **PDF 报告**:内置渲染脚本,输出可交付给同事/客户的脱敏 PDF

## 核心方法论

这个 skill 区别于"夸夸式分析"的几条硬原则:

| 原则 | 含义 |
| --- | --- |
| **拿不到后台数据就不编** | 完播率、留存、CTR 普通用户拿不到。只用公开数据(播放/赞/评/藏/转 + 评论),其余靠内容结构**推断**并明确标注是推断 |
| **作者得意之笔 ≠ 用户爆款驱动力** | 内容推断出的"精妙设计"必须在评论区找到证据,否则大幅降权。用户是情绪驱动,不是结构驱动 |
| **比例按类型校准** | 评赞比 1:117 在情感型视频里健康,在干货型里就是异常。先判类型再判比例 |
| **核心爆点 1–3 个就够** | 强迫排序。爆款靠 1–2 个尖锐爆点,不是 10 个平庸优点叠加 |
| **复刻清单要能开拍** | 选题变体要具体到一句话能开机,不写"可以做美食类的" |

## 输入支持

用户可以提供以下任意组合:

- 抖音链接 / 分享口令
- 视频文件(自动抽帧 + 音频分析,需环境支持)
- 脚本文字稿 + 公开数据
- 截图(封面、关键帧、评论区)

环境若具备数据获取工具链(分享链接解析、`ffmpeg` 抽帧、`whisper` 转写、公开数据 API),skill 会走自动化流水线;否则按清单引导用户手动补充素材。

## 使用方式

将本仓库放入 Claude Code 的 skills 目录:

```bash
git clone https://github.com/procmeans/rainwell-douyin-viral-analyzer.git \
  ~/.claude/skills/douyin-viral-analyzer
```

然后在对话里自然触发即可,例如:

- "分析这条抖音 [链接]"
- "拆解这个爆款,为什么它火了"
- "我想复刻这条视频,给我个脚本公式"
- "研究一下这个号最近的爆款"

## 仓库结构

```
SKILL.md                    # skill 主文件(分析框架 + 报告模板 + 方法论)
references/data-fetching.md # 自动化数据获取流水线与命令
scripts/render_pdf.py       # Markdown → PDF 渲染脚本
assets/report.css           # PDF 报告样式(A4、PingFang SC、红色 accent)
evals/evals.json            # 触发与质量评估用例
```

## 输出物

工作格式是 Markdown,**最终交付物是 PDF**。报告严格按固定模板输出(元信息 → 钩子 → 结构 → 情绪曲线 → 视听 → 数据比例 → 评论区 → 归因 → 复刻清单 → 一句话总结),并对所有工具/接口名称脱敏 —— 呈现立场是"我看过这条视频做的分析",而不是"我用了一堆工具拿数据"。
